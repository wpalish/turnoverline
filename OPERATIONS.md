# TurnoverLine · эксплуатация локального кандидата

Эти команды поставляются с исходниками. Реальный Linux-хост, DNS, сертификат, Caddy и systemd в этой задаче не настраивались. Локальная проверка описана в [PRE_RELEASE.md](PRE_RELEASE.md).

## Первый запуск и перезапуск

Нужен Node.js >=24.15 <25 со встроенным `node:sqlite`. Внешних npm-зависимостей нет. Запускайте от отдельного непривилегированного пользователя ОС. База по умолчанию — `.data/workspace.sqlite`; адрес — `http://127.0.0.1:8792`.

В своём терминале задайте первый пароль, не записывая его в командную строку или Git:

```sh
read -r -s WORK_ADMIN_PASSWORD
export WORK_ADMIN_PASSWORD
npm run preflight
npm start
```

`preflight` читает существующую базу, проверяет конфигурацию и нужные статические файлы. Он не создаёт базу и не меняет аккаунты. Первый `start` создаёт администратора; после успешного входа удалите bootstrap-пароль из окружения/файла конфигурации. Последующий запуск использует сохранённые аккаунты и сеансы. Переменная `WORK_ADMIN_PASSWORD` никогда не сбрасывает пароль существующего пользователя.

`SIGTERM`/`SIGINT` закрывают HTTP-сервер и SQLite, через пять секунд завершают оставшиеся HTTP-соединения. Ошибочная конфигурация даёт безопасное сообщение и код выхода78. Неожиданная ошибка не выводит внутренний текст исключения.

## Размещение за HTTPS

Шаблоны: [окружение](deploy/production.env.example), [Caddy](deploy/Caddyfile), [systemd](deploy/turnoverline.service). Они требуют проверки и настройки владельцем хоста:

1. Укажите отдельный hostname, фактический путь Node.js24 и путь репозитория. `PUBLIC_DOMAIN` в Caddy должен точно соответствовать `PUBLIC_ORIGIN` без `https://`; нестандартный HTTPS-порт также должен совпадать.
2. Настройте DNS/сертификат/reverse proxy. Приложение слушает loopback; наружу работает HTTPS proxy. `PUBLIC_ORIGIN` — только origin, без пути, параметров или учётных данных.
3. В production задайте `NODE_ENV=production`, явный HTTPS `PUBLIC_ORIGIN`, абсолютный `DATABASE_PATH`. Каталог БД должен быть приватным обычным каталогом, файл базы и существующие WAL/SHM/journal — приватными обычными файлами владельца, без symlink. Для нового каталога используйте0700; для файлов0600. Не исправляйте права чужих файлов вслепую.
4. Создайте отдельного пользователя сервиса и приватный файл окружения вне Git. В шаблоне systemd StateDirectory задаёт каталог0700, UMask0077; путь `/usr/local/bin/node` замените на фактический. Это шаблон, не установленная служба.
5. Проверьте конфигурацию командой `caddy validate --config …` и средствами systemd на целевой машине; затем проверьте HTTPS-вход, Origin, Secure cookie, перезапуск, health и восстановление копии именно на этом хосте.

HTTP допускается только с loopback origin и loopback bind. Производственный HTTP, открытый HTTP bind, чужой продукт/схема базы, symlink и небезопасные права отклоняются до запуска. Отдельные порты одного hostname не изолируют cookies; используйте отдельные доверенные hostname.

## Аккаунты, сеансы и health

В «Данные и доступ» администратор видит роли, число действующих сеансов и сроки их истечения в UTC. «Завершить все сеансы» завершает вход выбранного аккаунта; у своего аккаунта сохраняется текущий сеанс. Отозванный браузер возвращается на вход при следующем защищённом запросе. Пароли, токены и хеши в список/журнал отзыва не включаются. Это не блокировка аккаунта: с прежним паролем можно войти снова. Смены пароля, отключения пользователя и SSO в интерфейсе нет.

`GET /healthz` возвращает только готовность и идентификатор продукта. Он требует правильный Host и не раскрывает данные/аккаунты. Команда `npm run health` проверяет локальный backend с Host из `PUBLIC_ORIGIN` и общим сроком ожидания две секунды. Это проверка SQLite/наличия администратора, не доказательство доступности внешнего HTTPS и не мониторинг с уведомлениями.

## Полная резервная копия SQLite

JSON из интерфейса переносит только рабочие записи в пустую область; аккаунты, сеансы и журнал в него не входят. Для полной копии работающего SQLite используется встроенный online backup API Node, а не копирование только основного файла живой WAL-базы.

Пример: каталог назначения должен уже существовать, принадлежать текущему пользователю ОС и находиться в доверенной иерархии. Замените пути своими. Каждый файл назначения должен быть НОВЫМ:

```sh
node scripts/backup.mjs --database /var/lib/turnoverline/workspace.sqlite --output /var/backups/turnoverline/snapshot-2026-10-26.sqlite
node scripts/restore.mjs --input /var/backups/turnoverline/snapshot-2026-10-26.sqlite --output /var/lib/turnoverline/restored-2026-10-26.sqlite
```

Копия содержит все пять таблиц: рабочую область, аудит, аккаунты, сеансы и счётчики неудачных входов. Перед публикацией проверяются продукт, версия, точная схема, integrity/FK и предметные ограничения. Выходной файл0600 публикуется атомарным hard link без перезаписи. Существующие назначения/sidecar, symlink, небезопасная иерархия и чужой продукт отклоняются. Инструмент требует POSIX ownership, hard link и fsync на локальной файловой системе; сетевые/объектные хранилища не проверялись.

Полная копия не зашифрована и не подписана. Она содержит хеши паролей и действующие сеансы, поэтому храните её как секрет, с ограниченным доступом и собственным сроком хранения. Восстановленные сеансы сохраняют прежний срок действия; если копия могла утечь, одной командой restore проблему доступа не решить. JSON также не является криптографическим доказательством автора или прошлых прав.

`restore` создаёт НОВЫЙ файл и не переключает работающий сервер. Проверьте восстановленную копию отдельным локальным процессом с её `DATABASE_PATH`: прежний вход, записи/ревизию/историю и health. Для реального переключения остановите принадлежащий вам сервис, сохраните прежний файл, измените путь БД в конфигурации, выполните preflight, запустите и проверьте результат. Для возврата используйте сохранённый прежний путь. Не запускайте два сервиса на одном рабочем файле и не удаляйте рабочую базу/sidecar во время восстановления.

Справка: [Node24.19 SQLite backup](https://nodejs.org/download/release/v24.19.0/docs/api/sqlite.html#sqlitebackupsource-db-path-options), [Caddy reverse proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy), [automatic HTTPS](https://caddyserver.com/docs/automatic-https).
